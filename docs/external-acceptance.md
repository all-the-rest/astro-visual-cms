# External-project acceptance: bounded visual Markdown draft

Manual, local acceptance run for issue #15 on a disposable copy of the local
`reisinger.pictures` checkout. This is evidence for one configured prose node on
one real Astro Content Layer route. It does **not** establish general MDX
support, DOM-to-source provenance, issue #14/#16 write readiness, issue #18
loader support, or issue #1 acceptance.

## Isolation and provenance

- The source checkout was copied with an APFS clone (`cp -cR`) to a temporary
  directory outside the repository. `.git` and all `node_modules` directories
  were removed from the copy before installing dependencies. Ignored content
  was included.
- Original and copy were hashed over 19,806 files / 13,182,018,907 bytes
  (excluding `.git` and `node_modules`). Both trees produced the same aggregate
  SHA-256 digest `0138878c1685e4081929a7fd2dbb1638ec8a44002418c9f70b60f2b23ac2936a`
  and byte-identical per-file manifests. The manifests stay outside the
  repository because they contain private paths.
- After all acceptance, build and production-isolation checks, the original
  tree was hashed again and still matched the pre-run digest exactly.
- The copy received the packed `@all-the.rest/astro-visual-cms` 0.1.0 tarball
  built from this branch (at the time of this run the package still used its
  internal `@astro-visual-cms/editor` name; the bytes and version were the
  same). Only the copy's `package.json`, lockfile, `astro.config.mjs`
  and a private acceptance config/server shim were changed. No such file is
  committed.
- Production content text, paths and the target route are intentionally not
  recorded in this repository. They live only in the local, uncommitted
  acceptance config.

## Gaps found and fixed

1. **Satteri 0.10 compatibility.** The marker plugins called only
   `context.setField`, which exists in Satteri 0.11.6 (Astro 7.4.7) but not in
   Satteri 0.10.5 (Astro 7.4.1). The real route crashed with
   `context.setField is not a function`. The plugins now use `setField` when
   present, fall back to the 0.10 `setProperty` mutator, and otherwise leave the
   page readable without marking it. Unit tests cover both APIs and the
   no-mutator fallback.
2. **Editor UI depended on the consumer's Tailwind scan.** The editor page
   loaded only the target project's `src/styles/global.css`; classes used by the
   editor in `node_modules` were not generated by the consumer, so the preview
   wrapper lost `overflow-auto` and the editor page overflowed horizontally at
   mobile width. The package now ships a generated,
   self-contained `src/editor/editor.generated.css`, serves it from the editor
   origin, and loads it after the project stylesheet. A freshness gate
   (`pnpm run verify:editor-css`) fails if the generated file is stale. The
   synthetic demo's own Tailwind scan still includes `src/editor`, so its mobile
   browser assertion does not prove the shipped stylesheet on its own; the
   browser test additionally asserts that `/editor.css` is loaded, and the
   installed-tarball smoke checks its served content. A real consumer keeps the
   editor under `node_modules`, which Tailwind ignores. `alert-success`/
   `alert-error`, which are composed dynamically, are explicitly sourced into
   the generated file.
3. **Flaky duplicate-output browser assertions.** The synthetic copy tests fetched
   the duplicate page once, which could race Astro's watcher/HMR invalidation
   after the catalog endpoint had already re-read the file. Both the visual-draft
   and legacy Markdown assertions now poll the rendered route with a bounded
   timeout before requiring the marker to disappear.
4. **macOS test-root spelling.** The local macOS run used a canonical
   `TMPDIR`; one test still used the literal `/tmp` symlink for a config-path
   rejection. It now uses `realpathSync(tmpdir())`, so the intended
   project-relative rejection is tested on macOS and Linux without weakening
   production path checks. Issue #17 remains open for the broader canonical
   test-root cleanup.

## Open gates

- The visual draft is still limited to an explicitly configured, unique,
  root-level, single-line plain-text MDX paragraph. It is not a general
  Markdown/MDX editor and does not map arbitrary DOM output.
- No proposal/export, source-changing handoff or existing-file write is
  enabled by this path. The catalog and preview return only target text, the
  source revision and the exact text-range diff; there is no commit route.
  #14 and #16 remain open.
- The real `portfolio` collection remains read-only. #18 remains open.
- The external run is manual and local; it is not part of CI and does not prove
  every Astro 7 minor, every consumer, or production readiness.
- Issue #1 and #14 must not be closed from this evidence.
